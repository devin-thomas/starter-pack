# Maintaining the published style guides

TypeScript has a stable 1.0.0 core, Godot a stable 1.0.1 core, Kotlin a stable 1.0.0 core with an Android TV profile, React + TypeScript a stable 1.0.0 companion, and Rust a stable 1.0.0 core. Their accepted rules are published in `typescript.md`, `godot.md`, `kotlin.md`, `react-typescript.md`, and `rust.md`; metadata drives the human pages, Markdown, JSON, catalog, and discovery entries. Python, Swift + SwiftUI, JavaScript, and Dart + Flutter retain their separately recorded review statuses. Planning is not stored in public content.

Run `npm run format:style` when changing TypeScript code fences, then `npm run check`. The TypeScript checker compiles its examples with the accepted strict flags, checks explicit declaration contracts, tests rejected type operations, and runs executable behavior tests. The Godot release is hard-pinned to Godot 4.7.2; Starter Pack CI verifies its public 25-rule surface and metadata but does not claim to execute Godot without a pinned Godot binary. Project-level Godot enforcement belongs in the target Godot repository as described by G024. The Godot 1.0.1 examples and the G024 script gate were checked by hand against the official Godot 4.7.2 macOS build on 2026-09-25; repeat that check with a real 4.7.2 binary when changing GDScript examples.

Kotlin has 38 accepted rules, with K002 using native `val`/`var` binding semantics. Its companion pure Kotlin examples were compiled with `-Werror` and executed with Kotlin/JVM 1.9.0 on OpenJDK 21.0.11; an incomplete sealed-state consumer was rejected for the intended exhaustiveness diagnostic. This is not an Android build or a claim about a project's newer compiler. The guide's StateFlow fragment and Android/Compose guidance remain explicitly outside that executed core validation. Starter Pack CI checks publication structure and parity, not Kotlin compilation, emulator operation, or physical-device behavior. Project-specific versions and private deliberation are not public guide content.

`npm run verify:style` checks the built stable and review-guide resources, including Rust. `Style guide audit` checks browser reading, clipboard success and denial, mobile overflow, fragment navigation, and hidden internal decision IDs for all published guides. The Kotlin browser case expects 38 rules plus purpose, validation, and reference sections; TypeScript and Godot retain their existing 25-rule expectations. Rust has 36 rules plus four supporting sections. Pushes and pull requests run local checks; the workflow's optional `verify_live` dispatch verifies an already owner-approved deployment. The workflow runs with read-only repository permissions and does not deploy or mutate source.

The checker uses the repository's native TypeScript 7 executable for independent type checks. Its syntax-inspection pass uses the pinned `@typescript/typescript6` compatibility API because TypeScript 7.0 does not expose the classic compiler API. This split is deliberate; do not replace the actual compiler check with a parser-only check. The installed lockfile records the precise dependencies.

Guide-example enforcement does not claim that every legacy source file in Starter Pack has migrated to this house style. The React UI and feedback Worker additionally use the complete TypeScript safety baseline, readonly named data contracts, explicit component contracts and an application formatting gate. Workbench and build-script migration is partial; architectural rules and remaining boundary validation require review. The general D025 enforcement contract is tool-agnostic; this repository pins concrete checks for the examples and application.

Example markers are HTML comments and do not appear in the human reading surface. The three D023 module files form one small multi-file example; other blocks are checked independently. Do not convert illustrative route strings into real site paths to satisfy a link checker. Link checks must distinguish actual metadata/Markdown links from source-code examples.

Existing hosting-toolchain dependency debt discovered during the audit is tracked separately in issue #3. A passing guide release is not a blanket security certification of the hosting application.

## Completion and agent authority

When the owner accepts the final outstanding decision for a completed guide and no substantive choices remain, record the guide as finished, stable `1.0.0`, and accepted through its final rule. Do not invent a second guide-level approval gate or leave accepted guidance labeled provisional. Apply the status consistently to the guide, introduction, maintenance record, README, generated machine-readable resources, catalogs, and tests. Stable guides are authoritative for agent use; ordinary future improvements do not make an accepted version unfinished.

Track merge, deployment, live verification, and implementation-specific validation separately. These are delivery or evidence states, not reasons to relabel an accepted guide as in progress. A real unresolved decision must be identified specifically; do not infer approval of choices that have not been made. This Rust completion change does not silently resolve pending choices in other languages.

## Rust 1.0.0

Rust is finished and owner-approved: `status: stable`, `version: 1.0.0`, `accepted_through: RS036`. All 36 rules are authoritative. The final RS-Q01 B decision is accepted in RS025, and no additional guide-level approval remains. First-party unsafe may support necessary integration and a demonstrated systems/performance requirement under the stated boundary and verification conditions. The published rationale explains why those needs justify an explicit exception to the normal strictness; it does not treat unsafe as a generic optimization.

`rust.md` and `rust-intro.md` generate `/style/Rust`, its Markdown/JSON resources, catalog and discovery links. The shared renderer removes the `RS` rule prefix from human headings while preserving it in agent-readable source. The stable guide contains 36 numbered rules and four supporting sections. The existing `wip-style-guide-surfaces.mjs` command now verifies status per guide: Rust must be stable, with matching version and full acceptance in JSON/catalog metadata, no provisional badge, and no stale review wording. Its historical filename does not classify Rust as unfinished. Browser checks likewise use each guide's declared status.

On 2026-10-22, the nine Rust code fences were checked separately with Rust 1.90.0, edition 2024, rustfmt 1.8.0 (100 columns, style edition 2024), and Clippy 0.1.90. Compilation and lint used warnings as errors, with narrow allowances for standalone unused declarations and the deliberate explicit-unit policy. Twelve executable tests passed; an added unhandled enum variant was rejected with E0004. The 1.0.0 promotion leaves these examples and rules unchanged. This is example-level evidence, not a project MSRV commitment, runtime/FFI certification, or continuous Rust compilation in Starter Pack CI. Repeat an actual Rust check when changing these examples.
