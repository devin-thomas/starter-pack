# Build Something Meaningful

Build a small project you would actually use: a personal tracker, a searchable collection, a generator, or a prototype of a larger idea. Choose something you can finish. Save your most ambitious long-term project for the next phase.

## Bring your progress with you

Open your harness on a computer, or use an already reliable remote connection. Give your agent your existing progress file. Before substantive Phase 2 work, ask it to create or confirm a **private GitHub progress repository** using the [progress template](/artifacts/progress/README.md). It should contain your progress, computer setup status, and project notes. This website has no learner account and does not store your completion state.

## Complete Computer Setup

Tell your agent: **Run Starter Pack Computer Setup.** The [Computer Setup skill](/skills/computer-setup/current/SKILL.md) inspects your operating system and installed tools before proposing changes. Windows 11 and current macOS are first-class paths; Linux support is best effort.

Your agent presents one plain-English plan for the required tools and asks for batch approval. Existing working tools count. It pauses when you need to sign in, approve administrator access, or restart, and saves enough nonsecret state to resume. Optional tools are separate choices. Docker Desktop is only for projects that need containers and is installed last.

The baseline includes a harness, Git and GitHub CLI, Node LTS, Python through uv, search and JSON utilities, and Tailscale. You do not need to memorize these names or install every framework globally. The agent verifies that the tools work and records the results.

## Connect from your phone once

Install and sign in to Tailscale on your computer and phone. It provides a private network and device names; you also need an interaction app to control the computer or harness. Your agent helps choose a harness-native remote client, a suitable remote desktop, or SSH based on your equipment.

Connect to the computer by its Tailscale/MagicDNS name from your phone and complete one simple interaction with the harness. Tell your agent what worked. Installing Tailscale alone does not complete this step. If connection fails, keep the successful setup results and record the exact resume point. The computer setup milestone is complete after the required capabilities and this phone connection work, and the state is saved to your private progress repo.

## Have a short design conversation

Tell your agent: **Run Quick Build for my idea.** It will ask one compact round about what you want to make, who it is for, the main actions, your existing content, what to leave out, how it should feel, and what would count as done. Answer conversationally; you can leave routine technical choices to the agent.

The [Quick Build skill](/skills/quick-build/current/SKILL.md) turns that conversation into a plan, a specification, decisions, and ordered build tasks. You can inspect those documents, but learning their formats is not a prerequisite. The agent summarizes the intended result and waits for you to say **go** or request a revision.

## Build and put it online

Once you approve, the agent implements the smallest complete version in a durable project repository. Cloudflare is the default deployment platform. Vercel is an optional alternative when suitable. Neon comes into the build only if the project needs persistent relational data. Accounts, payments, and integrations are added only when they serve the product you approved.

Review the main behavior yourself and tell the agent what needs changing. Verification should fit the project and your testing preferences. Then deploy the project and open its live URL. A successful local build alone does not show that a deployed app works: try the main action at that live URL.

## Finish with something you can return to

Your finish line is a meaningful working project, source saved in a durable repository, a live deployment with its primary flow verified, and an updated private progress record. Keep the repository and live links with the result. If deployment or the live action still fails, record the remaining work and resume there rather than marking the phase complete.

When that is done, look ahead to [Build Something Serious](/phases/3).
